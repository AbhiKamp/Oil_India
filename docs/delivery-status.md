# Local prototype delivery status

Updated 20 October 2026. This records implementation, not the broader scope promised in the original architecture documents.

## Implemented local path

- Portable API service imports; typed, production-buildable dashboard client.
- Well-radius filtering using coordinates, per-well formation records, and an explicit synthetic active-well prognosis.
- Approximate formation-top-relative historical watch with actual source IDs and provenance.
- Persistent TXT/PDF upload, physical page references, event extraction, engineer review, and source-file access.
- Optional actual OCR via local Poppler/Tesseract; missing tools and unsuccessful recognition remain visible.
- Persistent engineer decision notes linking the active well to the historical offset event, with an evidence snapshot. Reviewer names are self-entered, not authentication.
- Normal/pack-off/kick deterministic replay; play/seek/reset API; per-well windows; timestamp-aware signal derivatives.
- Uncalibrated heuristic warning indicators, separately labeled from historical context. No incident countdown.
- Local lexical search and extractive source summaries; unsupported queries do not get randomly ranked pseudo-semantic evidence.
- A separate trained NumPy synthetic-pattern classifier, artifact validation, grouped holdout evaluation, and inspection endpoints. It does not drive warning severity.
- Remotion video workspace, browser capture tooling, and source/asset documentation. See the video workspace for current render and review status.

## Actual ML scope

The [experimental model report](../models/experimental/README.md) explains the generated dataset and grouped split. Windows before an injected anomaly are labeled normal; ambiguous transition windows are excluded. All scenarios for a synthetic well stay in the same partition. The small held-out set is generated by the same simulation family as training, so its scores do **not** estimate generalization to real wells.

The operational baseline remains explicit heuristic logic. It is not a trained XGBoost model or LSTM autoencoder. The synthetic classifier is current-pattern classification, not prospective incident prediction. A real OIL evaluation requires agreed event labels, causal horizons, unseen real wells, false-alert rates per operating hour, and qualified domain validation.

## Important limitations

- No production eRTMAC connection, rig control, field calibration, safety certification, or measured NPT reduction.
- No production authentication/RBAC; local reviewer identity is self-entered.
- No generative local language model. The assistant quotes relevant retrieved records with source links.
- Source extraction is a bounded prototype parser, not general layout understanding. Review remains required, especially for OCR, ambiguous units, and missing interval/datum fields.
- PDF parsing is bounded and runs off the event loop; it is not fully isolated in a memory-limited sandbox. Do not expose uploads as a public service.
- The spatial view is an interactive coordinate schematic, not a licensed tiled geographic basemap or a reconstructed reservoir model.
- Formation-top-relative MD mapping is illustrative; it does not account for all dip, faults, depth uncertainty, or datum differences. Unknown TVD stays null.
- Only the supplied active-well survey is available; other wells do not reuse its trajectory as if it were their own.
- Replay windows are in memory and reset on process restart. Knowledge, reviews, and handover decisions persist locally.
- Multi-user replay sessions, scalable retrieval, production ingestion queues, full drilling-program comparison, and broad multi-hazard prediction remain outside this local build.
- Film truth, comprehension, domain review, final voice/music approval, and competition upload permissions still require explicit release checks. A render is not a claim of submission readiness.
