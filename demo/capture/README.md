# Dashboard footage capture

For a fresh video workspace, install dependencies and Playwright's small FFmpeg recorder helper (this does not download a browser):

```sh
cd apps/video
npm ci
npx playwright install ffmpeg
cd ../..
```

Start a local API **with a disposable knowledge directory** and a production dashboard at the default URLs, then run from the repository root:

```sh
NWIS_DATA_DIR=/tmp/nwis-film-demo uvicorn apps.api.app.main:app --host 127.0.0.1 --port 8000
# separate terminal
cd apps/dashboard && npm run start -- --hostname 127.0.0.1 --port 41987
# repository root
node demo/capture/record-workflow.mjs
```

Uses `/usr/bin/chromium` by default (`CHROMIUM_PATH` overrides it), Playwright installed only in `apps/video`, a 1600×900 viewport, and role/label-based controls. Readiness is gated on rendered headings, API responses, offset results, a source dialog, review controls, and the acknowledgement/note UI; no fixed sleeps are used for readiness. `DASHBOARD_URL` and `CAPTURE_DIR` can override the dashboard address and output directory.

Outputs are written under `apps/video/public/captures/`: an uncut `workflow.webm`, named PNG checkpoints, and `shot-manifest.json`. The WebM is ignored by Git; PNGs and the JSON manifest stay trackable. The manifest records API statuses, revision, each shot purpose/hold, and an incomplete-run failure. Deliberate holds begin only after the relevant application/API state is verified. A take counts as complete only after the saved note is visible again following a page reload and the synthetic replay status is returned.

Recorded journey: change radius to 5 km and back to 50 km → compare a returned offset → inspect the historical watch and auto-scrolled cited text marker → upload a generated, labeled synthetic PDF → inspect and explicitly approve its physical-page extraction → see it enter the watch → save a handover note referencing that offset event and verify it after reload → run and pause a synthetic pack-off replay after its signals escalate. The PDF fixture is generated by the checked-in script and ignored as a binary.

The capture script clears only in-memory replay via `POST /demo/reset`. It does **not** delete prior PDFs, reviews, or handover records. Start the API using a disposable `NWIS_DATA_DIR`; use an isolated capture API, not the real user store. The script uses a run-unique note so another take does not produce duplicate UI matches. The take is considered complete only after source extraction has physical page provenance, reviewer approval changes eligibility, and the handover entry persists. The generated PDF fixture is written to `demo/capture/fixtures/`; recreate it with `python3 demo/capture/generate_synthetic_pdf.py`.
